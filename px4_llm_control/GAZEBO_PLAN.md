# Gazebo环境扩展方案（本次仅设计，未修改仿真文件）

建议分阶段完成，先跑通视觉与几何，再接自动飞行。现有gz_x500、DeepSeek节点继续可用。

## 1. 场景：新建独立的vlm_training世界

在后续获准实施时，基于本机PX4的Tools/simulation/gz/worlds/default.sdf新建vlm_training.sdf，
保留原默认世界；物体与传感器的文件单独保存，便于Git管理。保留物理、重力、磁场、
spherical_coordinates和必要传感器系统配置，不通过关闭飞控检查来掩盖环境错误。

首版使用24×24米训练区，起飞点在中心，半径3米起降区不放障碍。
所有场景物体都要有visual和collision；只加visual会出现看得见却可穿透的假障碍。
用简单本地几何体先跑通，不依赖联网下载大场景。

以下是**Gazebo世界ENU坐标**的示例布局（x东、y北、z上，米），不是PX4的NED指令：

| 物体 | 位置/尺寸示例 | 用途 |
|---|---|---|
| 红色箱子 | (6,0,0.75)，1.5×1.5×1.5 | 自然语言选目标、RGBD测距 |
| 蓝色圆柱 | (3,6,1)，半径0.5、高2 | 形状/颜色区分、同类干扰 |
| 黄色车辆模型 | (-6,4,0.5) | 静态定位后扩展为可控移动目标 |
| 独立立柱 | 多个位置，间距3–5米 | 绕行与狭窄通道 |
| 墙与门洞 | 训练区边侧，高4米，门宽先取3米 | 先固定高度，再三维绕障 |
| 同色不同位置的箱子 | 分散在视野两侧 | “左边那个”等指代表达与歧义测试 |

物体name用于记录实验真值，不能直接作为VLM的可见类别输入。
首轮静态环境，第二轮使用可重复轨迹的移动目标，第三轮才加入动态障碍与遮挡。
后续再加入真实纹理、光照变化和多种尺寸，避免只会识别理想纯色方块。

## 2. 载机与传感器

本机已存在x500_depth、x500_mono_cam、x500_lidar_front、x500_lidar_2d等模型。
先使用x500_depth验证RGB/深度接入；后续独立派生x500_vlm，增加前视RGBD和激光，
不要直接改坏原x500。向下测距仪主要用于高度，不足以支持前向避障。

当前OakD-Lite模型有RGB 1920×1080、FOV 1.204，以及深度640×480、FOV 1.274。
因此它们不是天然像素对齐的RGBD，简单resize深度无法保证正确配准。
方案二选一：
1. 实现相机内外参驱动的真实深度注册/投影，处理遮挡和空洞。
2. 第一阶段使用一致投影几何的RGBD传感器配置，验证对齐、CameraInfo和时间戳后再启用三维输出。

为性能考虑，初期RGB 640×480或768宽、10–15Hz，深度10–20Hz；
VLM只取最新帧0.5–2Hz，轻量视觉跟踪器之后以15–30Hz维持目标状态，
规划/控制环独立于VLM推理。不要为每个Offboard周期请求一次大模型。
激光先用2D扫描测试距离接口，最终三维障碍需要多线/3D点云，覆盖机体实际飞行体积。

## 3. Gazebo到ROS桥接与TF

PX4与ROS的MicroXRCEAgent链路用于飞控状态/控制，不会自动桥接相机图像。
另使用本机已有ros_gz_bridge桥接Image、CameraInfo、LaserScan、PointCloud2、/clock。
实际Gazebo话题先用gz topic -l确认，不硬编码未经验证的/world/...路径。

规划ROS接口：
- /camera/image_raw（建议发布校正RGB到此接口或重配节点rgb_topic）
- /camera/aligned_depth_to_color/image_raw
- /camera/camera_info
- /lidar/scan、/lidar/points
- /clock（与使用use_sim_time的节点一致）

需建立map/odom -> base_link -> camera_link -> camera_optical_frame及雷达外参。
外参静态、机体位姿动态；目标反投影使用图像时刻的TF，不能用推理结束时的最新位姿。
RGB、depth、内参统一真实光学语义；仅修改header.frame_id不会自动旋转数据或完成注册。
世界ENU与PX4 NED、机体FLU/FRD变换应由独立适配模块明确实现并测试。
Gazebo ground truth用于评测，正式感知链路不要偷用目标真值位置。

将来创建世界并配置后，可按本机启动脚本支持的方式运行：

```bash
cd /home/si/uav/learn/PX4-Autopilot
PX4_GZ_WORLD=vlm_training make px4_sitl gz_x500_depth
```

**此命令当前还不能用于启动新世界，因为vlm_training.sdf尚未创建。**
现有x500_depth可单独用于传感器接入测试；本次没有替你启动或修改仿真。

## 4. 到自主跟踪/避障/导航的后续模块

建议保持唯一飞行执行器，VLM只选择语义目标和任务，不直接输出任意电机或姿态控制：

```text
VLM语义选目标 -> 轻量跟踪器/目标状态估计 -> 目标世界位姿与跟随距离
RGBD/激光 + 机体位姿 -> 三维占据/ESDF -> 全局/局部路径规划
二者 -> 带速度/加速度/碰撞约束的局部轨迹 -> 唯一Offboard执行器 -> PX4
```

- 第一阶段：静态图像选红箱子，检查框、深度、TF，飞机先保持悬停。
- 第二阶段：已知空旷区低速目标跟踪，处理丢失、停止和最大跟随距离。
- 第三阶段：静态障碍建图和三维局部规划，可先用固定高度切片简化验证，但不能把2D避障称为完整三维避障。
- 第四阶段：动态目标/动态障碍，加入预测与重规划，再开放复合自然语言任务。

现有llm_control的path会在航点停顿，也没有在线碰撞验证，不能直接承担动态目标的高频重规划。
需要增加带时间戳、有效期、来源仲裁与反馈的轨迹执行接口，让文字任务和视觉任务共用同一个
PX4命令出口，而不是运行两个节点同时争抢/fmu/in设定点。
Nav2主要面向二维地面导航，不能直接当作多旋翼三维局部规划器。

## 5. 验收标准

先检查RGB/深度/内参频率与图像叠框；用已知物体距离量化像素定位/深度/TF误差。
再记录目标关联连续性、误选率、推理延迟分位数、丢帧/过期比例、最小障碍距离和轨迹跟踪误差。
模拟目标丢失、无效深度、激光断流、模型超时、TF缺失和Gazebo时间重置，
确认unknown/失效不被当作道路畅通。接飞行后必须验证这些情况能触发确定的悬停/降落或人工接管策略。
